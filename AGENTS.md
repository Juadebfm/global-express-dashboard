# Project instructions

## Accuracy and verification rule

Never hallucinate. Before answering, implementing, or coding, verify each
material claim from the relevant codebase, supplied documentation, or an
authoritative current source. If a required fact is unavailable, say: "I do
not know."

Do not make material product, architecture, authorization, or other judgement
calls without asking the user when the decision is not already specified by
the code or provided requirements. Do not invent facts, numbers, endpoints,
citations, or implementation assumptions.

For externally changing facts, use current authoritative sources or the
documents supplied by the user. Treat credentials and secrets as confidential:
never expose or persist them in notes or memory.

## Mandatory plain-language communication rule

Whenever explaining a term or describing an intended action to the user, use
plain, everyday language suitable for a layperson. If a technical term is
necessary, explain it immediately in simple words. This is a mandatory rule
for every user-facing explanation; it is not optional or conditional.
